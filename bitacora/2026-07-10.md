# Sesión 2026-07-10

## Cambios

### Fase 2 — Sistema de reservas
- **D1 + Drizzle**: esquema con 4 tablas (`services`, `availability_rules`, `availability_exceptions`, `bookings`), índice único parcial para evitar doble reserva, migraciones aplicadas en local y remoto
- **Generación de huecos**: `getAvailableSlots()` expande reglas L-V 10-14/16-19, resta excepciones y bookings, buffer 15 min, antelación mínima 24h
- **Página `/reservar`** (SSR): selector de servicio, calendario mensual vanilla JS, picker de horas dinámico, formulario con Turnstile
- **Astro Actions**: `getSlots` (consulta huecos) y `createBooking` (validación zod, verificación Turnstile, inserción D1, emails en segundo plano)
- **Emails vía Resend**: notificación al terapeuta + confirmación al cliente con `onboarding@resend.dev`
- **Turnstile**: verificación server-side, widget client-side con test keys en dev

### Fase 3 — Panel de administración
- **Auth**: cookie httpOnly firmada con HMAC-SHA256 (Web Crypto), 8h de validez
- **Middleware**: `src/middleware.ts` protege `/admin/*` y acciones de admin, redirige a login si no autenticado
- **Login**: `POST /admin/login` con contraseña, `Set-Cookie` en respuesta
- **Dashboard**: tabla de reservas próximas (pendiente/confirmada) con botones Confirmar/Cancelar + historial plegable
- **Acciones admin**: `confirmBooking`, `cancelBooking` (con emails al cliente), `cleanupTestBookings`
- **Logout**: limpia cookie y redirige a login

### Correcciones importantes
- `Astro.locals.runtime.env` eliminado en Astro v6 → migrado a `import { env } from 'cloudflare:workers'`
- `Astro.redirect()` no propaga headers personalizados → `new Response(null, { status: 302, headers: {...} })`
- `drizzle-orm` `with` (relations) no funciona en build de Workers → queries separadas con lookup
- `atob` no funciona con bytes binarios → `bytesToBase64url()` segura para cookies
- POST a páginas Astro requiere header `Origin` (CSRF) → protegido en navegador real
